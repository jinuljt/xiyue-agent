XIYUE · 喜悦

喜悦 Agent · 执行核心

本仓库是喜悦的设备端执行核心。v0.1 实现独立管理与任务运行；尚未接入麦克风、ASR、LLM、TTS 或外部 Agent，不能当作已完成的语音产品。

实现

  • Go 标准库，无第三方运行依赖；可构建 Linux ARMv7 静态二进制。实际音箱的内核兼容、内存、音频和稳定性仍待验证。
  • 声明式能力导入；配置字段自动供控制台生成表单；不执行插件中的任意代码。
  • 任务步骤 say / confirm / timer；确认、暂停、恢复、取消、重看提示。
  • 单次、每天、工作日调度；使用 IANA 时区和日历日期推进。
  • 状态通过临时文件、fsync 和原子重命名保存；写入失败不推进内存状态。目录 0700、文件 0600。
  • 计时重启后根据到期时间推进；离线期间错过的周期只补一次，后续恢复正常节奏。

运行与构建

go test -race ./...
go vet ./...
go run . -console ../xiyue-console -abilities ../xiyue-abilities/capabilities

CGO_ENABLED=0 GOOS=linux GOARCH=arm GOARM=7 go build -trimpath -ldflags="-s -w" -o dist/xiyue-agent-linux-armv7 .

单进程持有一个状态文件；不要让不同进程共享同一状态目录。首版保留最多 500 条任务、100 条计划、32 个能力和最近 200 条事件，不承担完整历史审计。

HTTP API v0.1

接口作用
GET /api/health真实服务接入状态
GET /api/state能力、任务、计划、事件快照
GET /api/tools已启用能力的描述；尚非 MCP 接口
POST /api/abilities安装声明式能力，同名拒绝覆盖
PUT /api/abilities/{id}保存 enabled 与 config
POST /api/tasks使用 ability_id、inputs 创建任务
POST /api/tasks/{id}/{action}confirm / pause / resume / cancel / repeat；附当前 index 和 status，防止旧确认跳过步骤
POST /api/schedules使用 ability_id、inputs、next_at、repeat、timezone 创建计划
DELETE /api/schedules/{id}删除计划

写操作要求 Content-Type: application/json 与 X-Xiyue-Request: console。监听仅限回环地址，限制 Host 和 Origin；这不代替正式设备配对，尚不能向局域网或互联网开放。

凭证与后续接入

credential_ref 只接受 bitwarden:item:条目UUID，不读取凭证，也不能插入播报文本。实际密钥输入、安全存储、设备侧取用与授权尚待实现。开发期间复用已授权凭证源，不在工程里创建真实凭证。系统 TTS 为目标默认；语音入口与网页操作必须通过同一任务 API。
