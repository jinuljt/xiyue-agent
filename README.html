XIYUE · 喜悦

喜悦 Agent · 执行核心

本仓库是喜悦的设备端执行核心。v0.2 已提供系统配置、能力管理、状态用量和手动文字模型 / HTTP Agent 调用。设备端语音入口支持 16 kHz WAV、自建 SenseVoice、豆包语音和系统播报。OH2P 本地唤醒事件可触发收音与灯效。唤醒词识别程序的部署，以及与原生小爱共存仍待真机验证。

配置与监控优先

控制台主要用于系统配置、能力配置与状态用量。任务、待办和菜谱等是扩展应用，不作为控制台首页的中心。

  • 基本设置：设备名称、唤醒词、时区和三种运行模式；保存不等于已经应用到真实音箱。
  • 服务设置：ASR / LLM / TTS / 外部 Agent 分开配置，支持留空保留或显式清除密钥。
  • 文字验证：兼容 Chat Completions 的文本模型，或喜悦 HTTP JSON Agent；仅用户点击后调用，不自动产生云服务请求。
  • 用量：记录真实调用结果、耗时和服务商返回的 Token，不保存提示词与回复，不估算未提供的 Token 或费用。

实现

  • Go 标准库和 Coder WebSocket，无外部 Go 运行时；可构建 Linux ARMv7 静态二进制。实际音箱的内核兼容、内存、音频和稳定性仍待验证。
  • 声明式能力导入；配置字段自动供控制台生成表单；不执行插件中的任意代码。
  • 任务步骤 say / confirm / timer；确认、暂停、恢复、取消、重看提示。
  • 单次、每天、工作日调度；使用 IANA 时区和日历日期推进。
  • 状态通过临时文件、fsync 和原子重命名保存；写入失败不推进内存状态。目录 0700、文件 0600。
  • 计时重启后根据到期时间推进；离线期间错过的周期只补一次，后续恢复正常节奏。

运行与构建

go test -race ./...
go vet ./...
go run . -console ../xiyue-console -abilities ../xiyue-abilities/capabilities

CGO_ENABLED=0 GOOS=linux GOARCH=arm GOARM=7 go build -trimpath -ldflags="-s -w" -o dist/xiyue-agent-linux-armv7 .

单进程持有一个状态文件；不要让不同进程共享同一状态目录。首版保留最多 500 条任务、100 条计划、32 个能力和最近 200 条事件，不承担完整历史审计。

GET /api/state能力、任务、计划、事件快照

写操作要求 Content-Type: application/json 与 X-Xiyue-Request: console。默认监听回环地址。局域网管理需按下文配置 HTTPS 和管理员登录；写操作限制 Host 和 Origin。

凭证与后续接入

系统服务密钥与能力的 secret 字段通过密码框提交，使用 AES-256-GCM 按字段名绑定加密；运行期密钥文件 0600，和状态文件一同留在被忽略的私有数据目录。普通配置与 API 读取仅返回是否配置，public state 不包含密文。留空保留旧密钥，显式清除才删除；更换服务商或地址必须重填或清除，避免把旧凭证发到新目标。请求不跟随重定向；非本机 HTTP 不发送密钥。

本地文件加密用于隔离普通配置与防止误导出，不抵御拥有该设备账户或 root 权限的访问。尚未提供可共享配置导出；运行状态文件不能作为普通配置分享。当前没有接入或迁移任何真实凭证。legacy credential_ref 继续支持高级凭证引用；普通用户配置不要求安装 Bitwarden。真实凭证接入应遵循部署环境的授权凭证源。

外部 HTTP Agent 的完整调用 URL 接收 POST JSON {"message":"用户文字"}，返回 {"reply":"回复文字"}，可选 Bearer 凭证。组合模式下，普通问答发给大模型。以「交给外部助手」开头的文字或语音发给此地址，前缀会在发送前移除。其他 Agent 需要实现同一接口或使用连接器。音箱系统 TTS 是默认输出。另可配置豆包语音合成 2.0，使用官方固定 HTTPS 服务、用户指定音色和 API Key。合成 PCM 交给设备的 aplay，从首个数据块开始播放。设备扬声器实际输出待验收。

设备端语音入口

在具备 /usr/sbin/tts_play.sh 的设备上启动 Agent 时可加 -system-voice。控制台会开放 SenseVoice 和豆包语音配置。SenseVoice 使用自建 HTTP 服务。使用以 /v1 结尾的 FunASR Base URL。支持可选 Bearer 凭证，以 sensevoice 为默认模型别名。豆包语音使用官方一句话识别 WSS 地址和新版 API Key，上传当前语音片段。豆包语音官方文档

第三方设备适配器可在开发模式把一次录音提交到回环地址的 POST /api/voice/turn。请求头设为 Content-Type: audio/wav 与 X-Xiyue-Request: console，正文为不超过 30 秒的 16 kHz 单声道 16 位 PCM WAV。一次只接受一轮语音。HTTPS 管理模式禁用 WAV 上传，本机唤醒走 Unix 套接字。返回识别、模型和播报阶段的耗时、不含录音或对话内容。目前系统播报通过固件脚本调用，实际打断和恢复行为待验证。

OH2P 上可另加 -oh2p-wake-socket /data/xiyue/run/wake.sock，让已安装的唤醒识别器调用 xiyue-agent -oh2p-wake-socket /data/xiyue/run/wake.sock -notify-wake 喜悦。套接字目录需限制为 0700。开发适配基于 OH2P 既有的 16 kHz 四声道 S32_LE 输入，只取第一个麦克风，忽略播放参考声道，由静音结束检测生成单声道 WAV。调用方也可提交 -cancel-voice。独立的唤醒词识别程序、录音阈值和原生小爱共存尚未在这一版本实测。

定时计划创建任务失败时保留原因。一次性计划可以在控制台手动重试，成功创建任务后才关闭计划。计划状态表示任务已创建。播报送达从任务提示记录中查看。

安装与管理员登录

安装完成时，在安装向导里设置用户名和密码。安装程序通过设备本机的私有套接字把设置交给运行中的 Agent。Agent 将带随机盐的 PBKDF2-SHA256 哈希写入状态文件，已有账号保持原样。局域网控制台负责登录，管理流量走 HTTPS。

安装器用 -admin-install-socket /data/xiyue/admin/install.sock 启动 Agent，再通过已验证的安装连接运行 xiyue-agent -provision-admin -admin-install-socket /data/xiyue/admin/install.sock。账号和密码以 JSON 送入标准输入。设备本机套接字目录权限为 0700。

管理员可在登录后直接设置新密码。保存时刷新当前登录并使旧会话失效。日常找回密码可以选「音箱确认登录」：先发起浏览器请求，在 60 秒内完成语音或实体键确认，再从控制台修改密码。语音依赖设备唤醒事件和已配置的 ASR，识别出的登录指令在模型路由之前处理。实体键使用 Linux evdev，无需网络语音服务。Linux 输入事件文档安装者需用 -admin-button-device、-admin-button-key 和 -admin-button-label 指定已经核对的音箱实体键。灯亮后连续短按两次。键位和灯效需在支持的固件上验收再启用。

定时播报和后台任务

说「计时三分钟」「三分钟后提醒我取茶」可直接创建本机计划。说「继续下一步」或「完成当前任务」时，仅在恰好有一条任务等待确认的情况下推进。首次音箱引导会在真实唤醒事件触发、完成模型回复并执行所配置的播报后收起。

设备语音启用后，任务的说话事件会进入持久播报队列。控制台区分待播报、已播报、失败、过期及中断。重启时曾领取而结果未知的提醒标记为中断，过期提醒不会自动补播。语音对话与提醒共用设备输出锁。

外部助手使用以 /v1/chat 结尾的喜悦连接器地址。后台任务在「任务与待办」里提交、查看和取消。喜悦仅存任务编号与绑定，不保存请求正文或回复。更换连接器地址或凭证后，之前对应的任务不再发往新目标。
